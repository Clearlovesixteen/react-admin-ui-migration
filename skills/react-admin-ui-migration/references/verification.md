# 验收与覆盖边界

## 能批量处理的工作

确认目标 API 和代表实现后，通常可以成组处理包导入、初始化配置、Layout 展示层、菜单搜索、Grid 搜索区、标准 Tabs、列表汇总位置及确定失效的样式补丁。扫描和模板减少重复工作，不提供未经实际评估的覆盖百分比。

以下内容逐项目核对：业务菜单真源与权限码、SSO/请求/日志、特殊 query/state 缓存、文件中心/我的应用接口、复杂组合查询映射、独有组件扩展，以及特殊报表/编辑器/拖拽页面。能从源码推导的正常适配由 Agent 完成；只有确实缺失的契约才询问用户。

## 静态检查

先读目标 AGENTS.md 和 package.json，再执行允许的命令。不要把本 skill 维护仓库的测试套件搬进业务仓库，也不要运行不存在的 test:page-layout。

静态审查至少覆盖：

- 声明、锁定、实际加载版本已区分；目标 registry 的查询结果、兼容候选、最终版本及升级/保持/受阻原因有记录。查询失败不能标记为最新；安装后版本与锁文件及实际 import 一致。
- 所有导入指向目标项目或已安装的组件包；没有插件缓存路径、维护者电脑路径或源系统 API。
- 目标项目只有一个正式 Layout 入口，路由、动态 import glob、菜单及权限数据保持一致。
- PageLayout 代码不进入 UI 组件包；组件配置没有已删除的 layout/listForm 字段。
- 全局 list/form/table 的作用域正确；纯表单弹窗和普通页面不会被列表默认值误伤。
- 被删除的旧配置、请求和状态确实有等价路径；业务参数和响应形状保持一致。
- 迁移过程中已有用户改动得到保留；未为通过检查跳过真实错误。

依赖升级时使用目标锁文件；没有用户要求时不同时升级整个开发工具链。

## 人工交互验收

目标要求不启服务或浏览器时，把这些作为待用户验证项，不声称已经验证：

| 场景 | 验收重点 |
| --- | --- |
| 登录和权限 | 公开页、无登录、无权限、按钮权限、退出和原平台入口 |
| 菜单 | 多层展开、父级高亮、折叠浮层、键盘 Escape、搜索不露出无权限项、外链和 redirect |
| 页签与缓存 | 新增/切换/关闭当前页、不同 query/state、原保活/刷新语义、拖拽后顺序 |
| 搜索 | 默认值、重置、展开收起、组合字段、自动查询、空值/零值、窄视口 |
| 表格和汇总 | 少量/空数据、长列、分页、排序、选择、刷新、汇总格式和单位 |
| 弹窗与抽屉 | 新增/编辑/复制/只读、校验、提交失败、成功后列表更新、复杂自定义项 |
| 高度 | container/child 两种滚动责任、KeepAlive 包裹、分页可达、无多余 body 滚动 |
| 异步反馈 | 首次请求期间显示 loading，完成且无数据才显示空态，错误提示保持 |

## 完成条件

每个适用单元有真实实现或“原已符合”的证据；受阻项、用户待验项与未运行的命令分别列出。未迁的旧页要列出路径，不能用“其余类似”掩盖遗漏。

交付概述：采用的 skill/模板基线、已完成范围、保持的关键业务契约、实际静态检查、未完成适配和人工验收。只有交互也得到对应证据后，才可以称完整验收通过。
