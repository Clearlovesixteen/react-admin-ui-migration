# 框架验收与迁移经验

## 覆盖表

每项记录执行、原已符合、受阻或不适用，附实现、保留的契约、实际证据。我的应用和完整框架的文件中心缺少服务时登记受阻，不以假数据交付。

| 层 | 检查 |
| --- | --- |
| 工程 | 本地及 CI Node/包管理器/唯一应用锁、项目 @gancao-web scope 源、锁定 tarball 地址、干净冻结安装、直接依赖、类型、lint、单元测试、test/pre/prod 构建、部署 base |
| 运行 | 开发服务和构建产物分别打开；懒加载/渲染错误定位到原异常，错误边界出现不代表页面可用 |
| 身份 | 未登录、SSO code、过期、退出、深链回原 URL、动态 header、换号和兼容旧 key |
| 权限 | 关闭无远程等待；开启成功/拒绝/失败/重试、旧码集合、父子关系、后台名称/排序 |
| 请求 | 旧新 payload/解包、分页、零值/空值、失败、软删除、上传地址/取消/进度 |
| 业务 | 全部开放页和相关弹窗、已关闭模块源码可编译但不可达、自定义编辑器/历史只读 |
| 平台 | 我的应用真实加载/搜索/重试/跳转；文件分页/搜索/下载/重试；不主动触发权限写入 |
| UI | 完整 CSS/主题、body portal、宽表、数字框、分页、搜索左边缘、折叠40×40、窄屏 |
| 缓存 | 原默认值、query/state、刷新、关闭当前页、已关闭缓存清理和未保存输入 |
| 清理 | 无运行中的 Umi/旧请求/@@ 别名、旧启动钩子/脚本、无人消费的兼容文件 |
| 合并/提交 | 合并旧分支后 scripts/生命周期/包管理器/锁仍一致，实际提交钩子和指定 Node 可用，不依赖跳过校验 |
| 回退 | 旧提交/产物和对应环境可重建；HTML/JS/CSS 整体切换；本地身份 key 策略清楚 |

先执行目标真实命令。资源包的测试入口不替代业务项目测试；构建成功、扫描零命中和 mock 的 37 项旧断言都不能覆盖真实 SSO、真实上传、不同权限账号或另一个项目。

浏览器不可用时继续静态与隔离验证，报告具体未验证点；不要换工具绕过已关闭的浏览器访问。恢复权限后补验实际错误与 UI，不能提前标记完整迁移。

## 已纳入资源的实证修正

- Jenkins 安装 @gancao-web 包误走公共镜像返回 404：项目安装根配置专用 scope 源，检查锁定下载地址；同时核对 CI 仍用 Node 16/pnpm 7 的独立工具链不匹配。资源、只读扫描、真实打包解包均覆盖该配置；离线测试不代表 Jenkins 实际安装成功。

- 组件包间接使用的 AntD Table/Cascader 缺样式：完整 Less + 主题 + 实际浮层验收；样式 mock 的测试无法发现。
- npm 转 pnpm 后隐式业务/测试依赖暴露：显式依赖与新的唯一安装锁，保留单元测试含义。
- 模板关闭角色权限仍等待接口、失败后不恢复：关闭直接 ready，开启有错误/重试，换号隔离旧响应。
- Store 的同 key 订阅与部分更新：精确解绑当前监听，以当前完整状态合并。
- UC 无参数调用未注入 sysId：统一 data:{} 再交 SDK。
- 上传主机和外链新窗口：目标文件 host 明确，外部 URL 不经过 hash 路由拼接。
- 旧权限码和远程名称/排序：保留显式 code，展示 metadata 与本地结构分开。
- Vite 8 + type:module 导入旧 Braft UMD 时保留导出对象，出现 Table/use 非函数：在专属编辑器入口显式解包，保留直接函数形状；Jest 的自动解包不能替代浏览器验证，详见 [运行时边界](styles-and-runtime.md#vite-8-与旧-umd-编辑器)。
- 旧表格插件在表单内省略按钮 type，插入会触发表单提交：编辑器边界取消默认提交并保留插件点击，测试外层 form 不触发，浏览器确认表格插入和无校验消息。
- 合并旧分支只带回 Umi 脚本/gitHooks，却删除 pnpm 锁：恢复匹配的新框架配置与锁后，实际钩子、冻结安装和构建均通过；扫描同时检查包脚本，不只看新依赖或源码。

这些是带条件的迁移边界，不把 CMS 的 APP_ID、页数、接口类名、登录字段或关闭权限默认值提升为所有项目的标准。新增经验应来自实际失败/验证，不追加没有证据的通用禁令。

## 新旧项目分流的实测边界

盘点工具已对实际 Umi 3 / React 17 项目、Vite 4 / 旧组件包项目和 Vite 8 / 新组件包模板做只读检查；Umi 走框架迁入，已有 Vite 走逐项补齐，真实旧运行时残留再进入混合架构处理。仅有 Vite 不能证明版本、请求、身份或平台能力已经符合，组件版本差异仍单独迁移。

实测发现注释里的旧导入会被误判为运行时残留，现已屏蔽独占行注释并保持原行号；回归同时检查注释样式不能充当完整 CSS 的证据，URL/正则中的斜线不受影响。扫描仍是词法导航，内联文本、动态导入和自定义包装需阅读调用方核实。

离线验证覆盖旧/混合/新架构 fixture、旧 Router、环境值不泄漏、资源不覆盖既有项目、实际打包/解包与框架资源闭包。它支持后续项目按该流程迁移；另一业务系统的真实登录、权限和写入合同仍需在该项目验证，不能用 CMS 结果替代。
